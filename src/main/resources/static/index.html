Crash one node mid-commit — another node finishes it

Every node shares PostgreSQL, Artemis and the LogCloud transaction log in PostgreSQL. Crash a node after the XA prepare: the node that leads recovery commits what was left behind — no restart, no local disk.

💀 All nodes are down. Start one with ./mvnw spring-boot:run, or docker compose --profile nodes up -d.

In-doubt (prepared) transactions in PostgreSQL

XIDPrepared

LogCloud transaction log and recovery leader

Not used in file mode: each node keeps its commit decisions in /app/transaction-logs on its own disk, and only that node can finish its transactions. Kill it and its in-doubt transaction stays above, holding its locks, until it comes back with that disk (docker start). Bring it back without it (docker rm, then up) and, minutes later, the new node rolls the transaction back — an order whose commit was already decided is lost.

LogCloud transaction log (table COORDINATOR)

TransactionStateRecovery domain

Every commit decision is written here before phase 2, and cleaned up shortly after both resources have committed. A row that stays while its node is down is a transaction left halfway — any node of the domain can finish it.

Recovery leader (table LEADER)

JVMLease

One node at a time runs recovery for the whole domain and renews its lease. When the leader dies (or hangs), its lease expires and another node takes over.
